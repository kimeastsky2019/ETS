원칙:

1. **이 문서가 기준이다.** 구현이 다르면 구현이 틀린 것으로 간주하고 보고한다. 단, §7의 "확인 필요" 항목은 예외 — 어느 쪽이 맞는지 판단하지 말고 차이만 기록한다.

## 2\. STEP 1 — 고영향 / 안전성 판단

### 2.1 고영향 체크리스트

| 그룹 | ID | 항목 | 배점 |
| :---- | :---- | :---- | :---- |
| A | A1 | 기존 모델보다 파라미터 증가, 학습 데이터 양 또는 유형의 확대 등으로 복잡도가 증가한 신규 모델에 기반한 AI시스템 | 2 |
| A | A2 | 1만명 이상의 금융소비자를 대상으로 하는 AI시스템 | 2 |
| A | A3 | 자동화 정도가 높고 속도가 빨라서 실질적으로 최종 의사결정에 관한 사람의 개입이 불가능한 AI시스템 | 2 |
| B | B1 | 대리 변수(Proxy Variable)를 활용하는 빈도가 높은 AI시스템 | 1 |
| B | B2 | 특정 업무영역을 위해 개발·고도화된 AI시스템을 다른 업무영역에 일시적 또는 단기간 활용하는 경우 | 1 |
| B | B3 | 국외 데이터를 주로 학습하여 개발된 국외 AI시스템을 활용하는 경우 | 1 |

**판정식 — 점수 합계가 아니다:**

```
고영향 = (A_해당수 >= 2) OR (A_해당수 == 1 AND B_해당수 >= 2)
```

> **최다 발생 버그**: 배점을 합산해 임계값과 비교하는 구현. 예를 들어 A1만 해당(2점) \+ B1·B2 해당(2점) \= 4점인데, 조합 규칙상 `A=1, B=2`이므로 **고영향 Yes**다. 반대로 B1·B2·B3 전부 해당(3점)이면 `A=0`이므로 **No**다. 점수 합산 방식으로는 이 둘을 구분할 수 없다. 표에 배점이 있는 이유는 A가 B보다 무겁다는 표시일 뿐, 판정에 쓰이지 않는다.

**근거**: 별첨04 「1. 영향&안전성 여부 판단서」 시트 하단 주석 — "A그룹 2개 항목 이상에 해당하거나 A그룹에 1개 및 B그룹에 2개에 해당하는 경우 '고영향 인공지능'에 해당됨". 상위 근거는 규정 「고영향 AI 판단」(붙임1).

### 2.2 안전성 대상 판단

**고영향 \= Yes 인 경우에만 수행한다.**

| ID | 항목 |
| :---- | :---- |
| S1 | 학습에 사용된 누적 연산량이 10^26 부동소수점연산(FLOPs) 이상인가 |
| S2 | AI 발전 수준을 고려할 때 최첨단 AI기술을 적용하여 구성·운영되고 있는가 |
| S3 | 사람의 생명·신체·기본권에 광범위하고 중대한 영향을 미칠 우려가 있는가 |

**판정식 — AND 조건이다:**

```
안전성_대상 = S1 AND S2 AND S3
```

> OR로 구현되어 있으면 결함이다. 규정 「안전성 확보 적용대상」은 "하기 기준을 **모두 충족**한 AI 시스템"이라고 명시한다.

판단 시점이 둘로 나뉜다 — **기획·설계 단계에서 사전 판단, 개발 단계에서 최종 판단.** 구현이 단계 구분 없이 1회만 수행한다면 기록해 둔다.

### 3.3 평가세트 (서비스 프로파일 4축)

별첨04 「2. 위험 식별 및 평가」 시트 상단에서 서비스 특성을 4축으로 선택하고, 그 결과로 32개 항목 중 일부만 **평가 대상**이 된다.

| 축 | 선택지 |
| :---- | :---- |
| 1-1 사용자 범위 | 대고객 서비스 / 임직원 서비스 |
| 1-2 산출물 특성 | 생성형 / 판단형 / 복합형(생성형+판단형) |
| 1-3 의사결정 영향도 | 인간결정형(HITL) / 인간감독형(HOTL) / 자율운영형(HOVL, HOUTL) |
| 1-4 데이터 민감도 | 비개인정보 / 개인정보 / 민감·신용정보 |

> **미확정 사항**: 4축 조합 → 32항목 중 어떤 항목이 평가 대상이 되는지의 매핑 규칙은 별첨04 수식 안에 숨어 있어 이 명세서에서 확정하지 못했다. 구현에 이 매핑이 있으면 **그 내용을 추출해 보고할 것.** 없으면 미구현으로 기록.

**주의 — 별첨04의 실제 동작**: 평가세트에서 제외된 항목이라도 위험 식별이 Yes이면 인식 위험 점수에 합산된다(예시 데이터의 4번 항목). 즉 평가세트는 **점수 계산 대상을 자르는 필터가 아니라 작성 안내**에 가깝다. 구현이 제외 항목을 점수에서 완전히 배제한다면 원본과 동작이 다르다.

### 3.4 점수 계산식

```
인식 위험 점수(항목)  = 배점            (위험 식별 = Yes 인 경우)
                     = 0               (위험 식별 = No)

완화 가중치(항목)     = 0.0   완전히 완화                      (○)
                     = 0.5   완화방안 적용 후에도 잔여위험 존재  (△)
                     = 1.0   완화방안 적용 후에도 위험수준 동일  (X)
                     = 1.0   완화방안 미적용                   (완화 여부 = No)

최종 잔여 위험(항목)  = 인식 위험 점수 × 완화 가중치

서비스 위험 점수     = Σ 최종 잔여 위험(전 항목)
```

검증 포인트:

- 위험 식별 \= No 인 항목은 완화 가중치와 무관하게 0이어야 한다  
- 완화방안 미적용(No)일 때 가중치가 1.0인지 확인 — 0으로 처리하면 중대 결함  
- 반올림 규칙: 0.5 가중치로 홀수 배점(1, 3)에 곱하면 0.5, 1.5가 나온다. 원본에 반올림 규정이 없다. 구현이 어떻게 처리하는지 기록할 것

### 3.5 등급 확정

| 위험 수준 | 하단 | 상단 |
| :---- | ----: | ----: |
| 허용불가 서비스 | 75 | 100 |
| 고위험 서비스 | 50 | 74 |
| 중위험 서비스 | 25 | 49 |
| 저위험 서비스 | 0 | 24 |

경계값은 **하단 포함**이다. 정확히 25점이면 중위험, 24점이면 저위험.

### 3.6 고영향 오버라이드 ★

```
IF 고영향 == True:
    최종_등급 = max(계산된_등급, 고위험)
```

**근거**: 규정 — "고영향 AI는 위험 점수에 따른 등급 분류와 관계없이 **고위험 AI로 자동 분류**하여 통제를 강화한다."

> 이 규칙은 별첨04의 등급 계산 시트에 명시적으로 나타나지 않으므로 **구현에서 누락되었을 가능성이 가장 높은 항목**이다. 최우선 확인. 점수가 0점이어도 고영향이면 고위험이어야 한다.

관련 정의(규정): "고영향 AI는 고위험 AI에 해당되나, 고위험 AI는 고영향 AI에 해당되지 않을 수 있다." — 즉 단방향 포함 관계다.

### 7-A. 보안성 원칙 배점 재배분

RMF 대비 **보안 \+2점, 위탁/관리 −2점**의 차이가 있다(§3.2). 다른 14개 항목은 정확히 일치. 부문 합계 30점과 총점 100점은 유지되므로 총점 검산으로는 발견되지 않는다.

구현이 어느 쪽을 따르는지 기록:

- (a) 별첨04와 동일 — 보안 10 / 위탁 6  
- (b) RMF와 동일 — 보안 8 / 위탁 8  
- (c) 제3의 값

### 7-B. 별첨04 예시 데이터의 시트 간 집계 불일치

「3. AI 위험 평가 보고서」 시트와 「평가 결과(요약)」 시트의 잔여 위험 점수가 일부 항목에서 다르게 나타난다. 상태가 "평가 수행 중"인 작성 중 템플릿이라 정상일 수 있으나, 구현이 어느 시트의 집계 로직을 따랐는지 확인한다.
